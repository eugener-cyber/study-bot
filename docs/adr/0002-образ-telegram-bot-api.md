# ADR-0002: Образ для локального Bot API server

**Дата:** 2026-09-27
**Статус:** accepted
**Затрагивает модули:** `docker-compose.yml`, все адаптеры источников

## Контекст

ТЗ §2.2 требует поднять локальный Bot API server на первом этапе: публичный Bot API не отдаёт файлы больше 20 МБ, а лекционное видео в этот лимит не помещается никогда. Переезд позже меняет способ получения файла во всех адаптерах сразу.

Telegram распространяет сервер **исходным кодом**, официального образа в Docker Hub не публикует. Нужно выбрать, откуда брать сборку.

## Решение

Использовать `aiogram/telegram-bot-api:latest` — сборку, которую поддерживает команда aiogram, той же библиотеки, на которой написан бот.

Переменные `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` передаются из `.env`; режим `TELEGRAM_LOCAL=1` включает выдачу файлов по локальному пути вместо HTTP-скачивания — ради чего сервер и ставится.

## Альтернативы

| Вариант | Почему отвергнут |
|---|---|
| Собирать из исходников Telegram своим `Dockerfile` | Сборка занимает десятки минут и тянет весь toolchain C++. Для проекта, где сервер — инфраструктурная деталь, цена не окупается |
| Произвольный сторонний образ из Docker Hub | Сервер получает `api_hash` аккаунта владельца. Образ от сопровождающих aiogram — меньший риск, чем образ неизвестного автора |
| Обойтись публичным Bot API | Прямо запрещено §2.2 с объяснением причины |

## Последствия

Проще: контейнер поднимается одной строкой compose, обновляется сменой тега.

Сложнее: появляется зависимость от стороннего сопровождающего. Если образ перестанет обновляться, остаётся путь сборки из исходников — он всегда доступен, просто дороже.

**Тег `latest` — временное решение.** Перед первым развёртыванием в эксплуатацию его следует заменить на конкретную версию: `latest` ломает воспроизводимость сборки. Зафиксировано как задача этапа развёртывания, не WP-01.
