# studybot

Telegram-бот: конспекты, задания и интервальное повторение по загруженным учебным материалам.

Пользователь присылает материал — бот строит конспект, банк заданий четырёх типов и сам возвращает к теме по расписанию интервального повторения, пока знание не закрепится. Не SaaS: один-несколько пользователей по белому списку.

**Метрика успеха** — не число конспектов и не время в боте, а доля правильных ответов на увеличенных интервалах, 7 и 30 дней.

## Запуск

Нужны Docker и Docker Compose.

```bash
cp .env.example .env     # заполнить значения, см. комментарии в файле
docker compose up -d
docker compose ps        # все четыре контейнера должны быть healthy
```

Четыре контейнера: `postgres`, `redis`, `telegram-bot-api`, `app`. Данные — в томах `./data`.

Локальный Bot API server (`telegram-bot-api`) обязателен с первого этапа: публичный Bot API не отдаёт файлы больше 20 МБ. Ему нужны `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` с `my.telegram.org` — они выдаются по номеру телефона владельца аккаунта и токеном бота не заменяются.

## Разработка

```bash
make install   # venv и зависимости
make check     # ruff + black --check + mypy --strict core/ + pytest
```

`make check` — ровно то, что выполняет CI: workflow вызывает эту цель, а не повторяет цепочку команд.

Тесты не ходят в сеть: `pytest-socket` блокирует её везде, кроме тестов с маркером `live`.

## Где что лежит

```
bot/          хендлеры, middleware, точка входа — только разбор апдейта и рендер
core/         бизнес-логика, конфигурация, логирование
docs/         ТЗ.md и План_реализации.md — канонические копии
docker/       Dockerfile образа приложения
tests/
CLAUDE.md     инварианты, конвенции, процесс — читается каждой сессией
STATE.md      состояние работ и открытые вопросы
```

Полная структура — `docs/ТЗ.md` §2.3. Пакеты создаются по мере надобности.

## Процесс

Разработка ведётся по двухагентной схеме: каждая задача проходит через Разработчика и Проверяющего с независимыми контекстами. Issue → План разработчика → approve плана → ветка → PR → ревью по чек-листу → merge. Без approve плана код не пишется.

Подробности — `CLAUDE.md` и `docs/ТЗ.md` §41.

## Секреты

Репозиторий публичный. Реальные значения `BOT_TOKEN`, `TELEGRAM_API_HASH` и `ALLOWED_USER_IDS` существуют только в локальном `.env`, который в `.gitignore`. В `.env.example` и `.env.ci` — плейсхолдеры.
